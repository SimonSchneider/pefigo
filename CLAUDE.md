# CLAUDE.md

## Project Overview

PeFi (Personal Finance) - a personal wealth management and financial forecasting MPA with server-side rendering. Built with Go, Templ, HTMX, TailwindCSS/DaisyUI, and SQLite.

## Tech Stack

- **Backend:** Go 1.25, custom HTTP server with `goslu` utility library
- **Database:** SQLite (via `ncruces/go-sqlite3`), SQLC for type-safe query generation
- **Templates:** Templ (`.templ` files generate Go code)
- **Frontend:** HTMX (minimal JS), TailwindCSS + DaisyUI, ECharts for visualizations
- **Architecture:** MPA with SSR; `controller` / `model` / `view` packages, one file per feature within each

## Common Commands

```bash
make run              # Dev server on :3002 with in-memory DB
make generate         # Generate SQLC, Templ, and TailwindCSS (run after changing .templ, .sql, or styles)
make generate-watch   # Same as generate but skips templ (use when watch-templ is running)
make watch-templ      # Templ hot-reload with proxy (primary dev workflow)
make watch-tw         # Watch TailwindCSS for changes
make docker-build     # Build Docker image with Podman
go test ./...         # Run all tests
go build ./...        # Verify compilation
```

**IMPORTANT:** The user runs `make watch-templ` during development. Never run `make generate` as it will crash the templ watcher. Use `make generate-watch` instead, which skips templ generation (the watcher handles it automatically).

## Project Structure

```
cmd/main.go                        # Entry point, delegates to controller.Run()
internal/
  controller/                      # HTTP layer
    handler.go                     # Route registration and handlers
    form.go                        # Form decoding (FromForm implementations)
    run.go                         # App startup & server config
  model/                           # Domain logic: model.Service methods, one {feature}.go per feature
  view/                            # Templ templates, {feature}_view.templ per feature
    view.go                        # Aliases for the model types templates use
  pdb/                             # Generated SQLC database code (DO NOT EDIT)
pkg/
  finance/                         # Financial forecasting engine (Monte Carlo, growth models)
  uncertain/                       # Probabilistic value handling
  swe/                             # Swedish salary, tax, pension, ISK and parental leave rules
  currency/                        # Currencies and exchange rates
  ui/                              # UI utilities (formatting, parsing)
static/
  migrations/*.sql                 # SQLite migrations (numbered sequentially)
  public/                          # Static assets (CSS, JS, images)
sqlc/
  queries/*.sql                    # SQL query definitions for SQLC
  sqlc.yml                         # SQLC configuration
tailwind/                          # TailwindCSS source + DaisyUI config
```

## Feature Implementation Pattern

When adding a new feature, follow this order:

1. **Database:** Add migration in `static/migrations/*.sql`, add queries in `sqlc/queries/*.sql`
2. **Generate:** Run `make generate-watch` to create Go code from SQL and templates (templ is handled by the watcher)
3. **Business logic:** Create `internal/model/{feature}.go` with types and `Service` methods (CRUD, page data)
4. **Views:** Create `internal/view/{feature}_view.templ` with page, list, edit, and form components; alias any new model types the templates use in `internal/view/view.go`
5. **Routes:** Register routes and handlers in `internal/controller/handler.go`; add form decoding in `internal/controller/form.go`
6. **Navigation:** Add nav item in `internal/view/view_main.templ`, icon in `internal/view/view_icons.templ`

## Code Patterns

- HTTP handlers use `errHandler`, which answers `model.ErrInvalidInput` with 400; entity saves and deletes go through `upsertHandler`, `deleteHandler` or `deleteWithLookupHandler`
- Model input types own validation (wrapping `model.ErrInvalidInput`), defaults and units; a `FromForm` only maps form fields with the `ui` parsers
- Files in `internal/pdb/` are auto-generated by SQLC — never edit manually
- Files ending in `_templ.go` are auto-generated by Templ — never edit manually
- Always run `make generate-watch` after modifying `.sql` files (templ changes are picked up automatically by the watcher)

## Key Conventions

- Minimal JavaScript — prefer HTMX and server-side rendering
- No explicit linter configured; use standard Go formatting (`gofmt`)
- Tests exist in `internal/model/` and `pkg/` — run with `go test ./...`
- Avoid dependencies when possible
- Always use Red Green TDD when doing any changes.

## Pull requests

Finished work ends as a pushed PR, without waiting to be asked. Before every push, run `make ci-pr` (tests, formatting, build, bench, Docker image) until it passes.

- **Finished an implementation:** commit, push the branch and open a PR. Write the body with the `pr` skill.
- **Finished an update to an open PR** (review feedback, follow-up changes): commit, push to the PR's branch, then rewrite the body with `gh pr edit <number> --body-file <file>` so its Summary, Evidence and Merge Danger describe the PR as it now stands.
